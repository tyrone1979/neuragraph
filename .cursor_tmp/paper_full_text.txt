NeuraGraph: A Visual Workflow Framework for Reproducible Biomedical Text Mining with LLM-AgentsLei Zhao1, Changning Ren2, Xinning Liu2, Li Han2, Yingnan Fan2, Ling Kang1∗, Quan Guo1∗1 Neusoft Research Institution, Dalian Neusoft University of Information, Dalian, 116023, China2 Software Department, Dalian Neusoft University of Information, Dalian, 116023, China*To whom correspondence should be addressed.Email: kangling@neusoft.edu.cn, guoquan@neusoft.edu.cn, AbstractSummary: Biomedical text mining increasingly demands hybrid pipelines integrating traditional NLP toolkits and LLM-based agents, yet orchestrating these heterogeneous components into reproducible workflows remains a major barrier for domain researchers without extensive coding expertise. NeuraGraph is a lightweight, open-source Python framework tailored for biomedical text mining, enabling minimal-code visual assembly of LLM-agent workflows with formal graph validation, recursive subgraph composition, and LLM-powered reporting. It features native parsers for biomedical benchmarks (CDR, ChemDisGene), one-line integration of local models (e.g., Flair), and out-of-the-box micro/macro metric logging—all with zero infrastructure dependencies. NeuraGraph was evaluated on chemical/disease named entity recognition and chemical-induced disease relation extraction tasks using the BioCreative V CDR benchmark. Compared with custom Python implementations and Dify-based workflows under functionally equivalent settings, NeuraGraph substantially reduced workflow engineering complexity while maintaining equivalent biomedical extraction and evaluation capability. NeuraGraph streamlines experiment setup from hours to minutes while enabling reproducible workflow execution for systematic hybrid extraction strategy comparison.Availability and Implementation: NeuraGraph is implemented in Python 3.12+ and released under the MIT license, with all dependencies listed in a requirements.txt file for straightforward installation. Source code and documentation are available at https://github.com/tyrone1979/neuragraph. The software runs natively on Linux, macOS, and Windows with no mandatory external dependencies.Contact:  zhaolei@neusoft.edu.cnSupplementary information: Supplementary data are available at Bioinformatics online.1 IntroductionBiomedical text mining is a cornerstone of translational bioinformatics, the discipline that bridges basic biomedical research and clinical practice(Cohen and Hunter 2013). It enables the extraction of actionable insights, e.g., chemical-disease relations, gene-phenotype associations from unstructured scientific literature (Lan et al. 2025, Xu and Sankar 2025).  Text mining has been successfully applied across the translational spectrum: in drug discovery (Öztürk, Özgür, and Ozkirimli 2018), pharmacovigilance (Karimi et al. 2015) , and precision medicine from clinical narratives(Wei et al. 2020). Modern mining pipelines increasingly adopt a hybrid paradigm that combines the reproducibility of traditional modular NLP tools such as Flair(Akbik et al. 2019) and SciSpacy(Neumann et al. 2019) with large language model based agents(Zhao, Kang, and Guo 2025). Recent surveys have documented this trend, showing that hybrid approaches consistently outperform purely traditional or purely LLM-based systems (Huang et al. 2025). This integration unlocks state-of-the-art performance for tasks such as named entity recognition (NER) and relation extraction (RE) on biomedical benchmarks (Jin, Choi, and Kim 2025, Lv et al. 2025), but introduces critical engineering challenges for biomedical researchers without extensive coding expertise. A central bottleneck in hybrid pipeline development is the orchestration of heterogeneous components into reproducible, evaluable workflows. General purpose workflow frameworks like LangChain and LangGraph(LangChain Team 2024) provide rich orchestration primitives but demand substantial coding effort, offer no built‑in support for biomedical benchmarks, and lack automated experiment logging and evaluation. On the other hand, low‑code platforms such as Dify(Dify 2025) and Flowise(Flowise 2023) are designed for production deployment, introduce infrastructure dependencies such as Docker, and do not facilitate fine‑grained, per‑instance error analysis required for methodical research. As a result, practitioners rely on ad-hoc scripting, hindering reproducibility and systematic comparison of extraction strategies.To address these gaps, we present NeuraGraph, a lightweight, open-source workflow framework designed for reproducible biomedical text mining with hybrid LLM-agent pipelines. Building on a LangGraph core, NeuraGraph introduces three key innovations tailored to domain researchers: (1) formal input inference that statically validates workflow graphs to eliminate runtime data dependency errors; (2) recursive subgraph composition as a first-class primitive for hierarchical pipeline design and reuse; and (3) an LLM-powered reporting agent that converts raw logs into structured reports with quantitative metrics and qualitative failure pattern interpretation.NeuraGraph is engineered for immediate usability: it ships with native parsers for established biomedical benchmarks such as BioCreative V CDR corpus (Li et al. 2016) and the ChemDisGene (Zhang et al. 2022) dataset, a browser-based visual editor with no code requirements, a secure plugin system for one-line integration of local biomedical NLP models, and automatic persistence of all experiment metadata as version-controllable JSON files. Unlike existing tools, NeuraGraph combines formal workflow validation, hierarchical subgraph reuse, and an LLM-powered reporting in a zero-infrastructure, pure-Python environment—eliminating engineering overhead while guaranteeing full reproducibility. NeuraGraph does not aim to introduce a novel biomedical extraction model. Instead, its primary contribution is a reproducible low-code workflow framework that enables biomedical researchers to rapidly assemble, evaluate, reproduce, and refine hybrid LLM-agent extraction pipelines under standardized experimental conditions.2 ImplementationNeuraGraph is implemented in Python 3.12+ and distributed under the MIT open-source license, with all core and optional dependencies explicitly listed in a requirements.txt file for straightforward installation. The framework requires no mandatory infrastructure dependencies (e.g., Docker, cloud services) and runs natively on consumer-grade hardware typical of biomedical research labs, including laptops with Intel i7 processors and 16 GB RAM. Resource-intensive LLM inference is decoupled from core execution and supported via lightweight API calls to lab-managed GPU servers running Ollama, ensuring compatibility with restricted network environments.The framework embeds a suite of integrated functional modules optimized for end-to-end biomedical text mining pipeline development and validation, with key capabilities including:Input and output specification, NeuraGraph accepts a dataset (raw text or annotated corpus like CDR/ChemDisGene) and a workflow graph (visual editor or JSON). Outputs include: (i) per‑instance predictions, (ii) evaluation metrics (micro/macro P/R/F1) when gold labels are provided, and (iii) a JSON artifact capturing workflow configuration, execution traces, predictions, and metrics. This JSON artifact serves as the complete record of an experiment, enabling full reproducibility. For unlabeled text (no gold annotations), the framework produces perinstance predictions and the same JSON artifact structure, excluding evaluation metrics supporting realworld deployment where ground truth is unavailable.Builtin components and user workflow, NeuraGraph ships with 36 prebuilt agents (15 LLM, 17 PGM, 4 SUB) covering the full pipeline of biomedical text mining.The framework supports recursive subgraph composition, allowing any complete workflow to be encapsulated as a reusable node for hierarchical pipeline design—such as sentence-level named entity recognition (NER) within document-level relation extraction (RE). This modularity enables the creation of lab-specific libraries of portable biomedical text mining components, shared as JSON artifacts for immediate reuse across experiments.Local biomedical NLP models (e.g., Flair) are integrated via a secure plugin system, with plugins isolated and cached after initial loading to prevent version conflicts. The plugin system ensures isolation through a unified base class design with namespace separation. Each plugin inherits from the base Plugin class and implements a load() method that returns a dictionary of exposed capabilities. All necessary dependencies (e.g., Flair, Hugging Face Transformers) are imported within the plugin’s methods rather than at the module level, localizing dependency usage to the plugin scope and preventing namespace pollution of the core framework. Plugin instances are cached after initial loading, and subsequent invocations reuse the cached instance to avoid redundant memory allocation and initialization overhead. This design maintains stability by ensuring that plugin execution remains self-contained and does not introduce unintended side effects to the core orchestrator. Pre-built plugins for common biomedical models are included, and a minimal template (≤50 lines of code) supports integration of custom local models for domain-specific tasks. All plugin interactions are managed within the core framework, requiring no additional configuration from end users.Every experiment execution generates a self-contained JSON artifact that captures the complete experimental context: workflow configuration, input dataset, per-node execution traces, intermediate outputs, final predictions, and instance-level evaluation metrics. These artifacts enable one-command reproducibility, with identical results generated on any compatible installation of NeuraGraph. An LLM-powered reporting agent ingests these JSON logs to compute micro-averaged and macro-averaged precision, recall, and F1 scores, producing structured Markdown reports with performance summaries and natural-language interpretation of failure patterns. The reporting agent supports both local LLMs (e.g., Mistral 7B via Ollama) and cloud-based LLMs (e.g., GPT-4o), configurable via a simple settings panel to accommodate research labs with restricted internet access.The end-to-end workflow of NeuraGraph, from data input to LLM-powered reporting, is illustrated in Fig. 1. For users needing additional datasets or models, custom parsers and plugins can be added with ≤50 lines of Python following the templates in the supplementary material.3 Results3.1 Biomedical Text Mining Workflow EvaluationNeuraGraph was evaluated on chemical/disease named entity recognition (NER) and chemical-induced disease (CID) relation extraction (RE) tasks using the BioCreative V CDR benchmark, a widely used benchmark for biomedical information extraction.The evaluation employed identical core extraction components across all implementations, including HunFlair2 for NER, GPT-4o/Mistral 7B for LLM-based relation verification, and micro/macro precision, recall, and F1-score for evaluation.To demonstrate practical applicability in a realistic pharmacological text mining scenario, an end-to-end workflow was constructed for automatic extraction of chemical-induced disease associations from biomedical literature.The workflow combines traditional biomedical NLP components with LLM-based reasoning agents in a hierarchical pipeline structure. Biomedical abstracts are first processed using a sentence-level NER subgraph to identify chemical and disease entities. Candidate chemical–disease pairs are then generated programmatically and verified using LLM-based relation extraction agents.Recursive subgraph composition enabled reusable sentence-level and pairwise processing components while simplifying workflow orchestration and reducing post-processing complexity.3.2 Quantitative Performance and Workflow EfficiencyTable 2 summarizes the quantitative performance of the NeuraGraph workflows on the BioCreative V CDR benchmark.Table 2. These results illustrate that NeuraGraph balances low-code accessibility with functional completeness, achieving substantial implementation effort reduction without sacrificing the ability to incorporate domainspecific models and evaluation standards. NeuraGraph enabled minimal-code workflow assembly, with a NER pipeline and a hierarchical recursive subgraph RE pipeline constructed through the visual editor. Full local execution and structured JSON artifact generation were completed in less than 10 minutes for all workflows.By contrast, custom Python implementations required extensive manual orchestration, environment configuration, debugging, and metric calculation. Dify-based workflows required additional prompt engineering, API configuration, and Docker-based infrastructure setup for local model integration.Compared with existing approaches, NeuraGraph substantially reduced workflow engineering overhead while maintaining equivalent biomedical extraction functionality and evaluation capability.3.3 Recursive Subgraph Benefits: A Concrete ExampleTo clarify how recursive subgraph composition reduces noise in nested pipeline execution, we provide a concrete example from the NER workflow. The recursive subgraph encapsulates sentence-level processing, isolating HunFlair2 model inference within each individual sentence. This isolation prevents cross-sentence interference—a common failure mode in flat pipeline implementations where entity spans (e.g., a chemical mention spanning a sentence boundary) are erroneously merged or truncated. Furthermore, the subgraph automatically aggregates outputs per sentence into a unified document-level structure, eliminating the need for manual post-processing code that often introduces alignment errors or off-by-one mistakes in custom scripts. Thus, noise reduction stems from both execution isolation and built-in aggregation, rather than from any modification to the underlying NLP models.3.4 LLM-powered Reporting and ReproducibilityThe built-in LLM-powered reporting agent automatically analyzed persisted workflow artifacts to generate structured Markdown evaluation reports containing quantitative metrics, error breakdowns, and qualitative interpretations of workflow failures.The reporting system consistently identified recurring error patterns across the CID extraction workflow, including over-prediction of weak chemical–disease associations, ambiguity in disease normalization, and false-positive relations triggered by entity co-occurrence without sufficient causal evidence. Based on these analyses, the system generated actionable refinement suggestions for iterative workflow optimization.All NeuraGraph executions generated self-contained JSON artifacts capturing workflow configuration, execution traces, intermediate outputs, predictions, and evaluation metrics, enabling one-command reproducibility across compatible installations. Metrics were aggregated at the article level to avoid pseudoreplication bias introduced by sentence-level aggregation.3.5 Generalizability to Other Biomedical Datasets and TasksWhile the evaluation focuses on the CDR corpus for NER and RE tasks, NeuraGraph is designed for generalizability across a wide range of biomedical text mining applications. The framework’s native parsers follow a modular design that can be extended to new datasets by implementing a dataset-specific parser inheriting from the base Parser class. For example, users can adapt NeuraGraph to gene-disease association extraction using the ChemDisGene corpus, or to clinical note analysis using i2b2 datasets, with minimal additional coding.For tasks beyond those natively supported, users can leverage the same visual workflow assembly approach, substituting domain-appropriate models via the plugin system (e.g., BioBERT for clinical text NER, PubMedBERT for gene mention recognition). The primary requirements for adapting NeuraGraph to a new domain are: (i) a well-defined input data schema (e.g., raw text with annotations), (ii) compatible NLP models or LLM agents for the target task, and (iii) task-appropriate evaluation metrics. These can be configured through the framework’s metadata system without modifying core code. Thus, NeuraGraph serves as a general-purpose platform for reproducible biomedical text mining beyond the CDR benchmark.End-to-end workflow examples for NER and CID relation extraction tasks, together with per-instance performance metrics, structured output artifacts, and automatically generated reporting examples, are provided in the supplementary material.Overall, these results demonstrate that NeuraGraph functions not merely as a visual workflow tool, but as a reproducible experimental platform for biomedical information extraction, enabling quantitative evaluation, structured error analysis, and low-code orchestration of hybrid LLM-agent pipelines.4 LimitationsDespite its demonstrated benefits for reproducible biomedical text mining, NeuraGraph has several limitations that should be acknowledged.LLM API dependency. The LLM-powered agents (relation extraction, sentence split, reporting) currently rely on API access to either local Ollama instances or cloud-based LLM services (e.g., GPT-4o via OpenAI-compatible APIs). While the framework supports offline operation using preloaded local models (e.g., Flair for NER), users without a local GPU server or with restricted network environments may experience reduced functionality or increased latency. All nonLLM components (parsers, PGM agents, metric calculation, workflow orchestration) run entirely offline with no external dependencies.Singlemachine scalability. NeuraGraph is optimized for singlemachine execution on consumergrade hardware typical of biomedical research labs (e.g., Intel i7, 16GB RAM). Distributed or largescale parallel execution (e.g., processing millions of abstracts across a compute cluster) is not yet supported. Workflows requiring highthroughput processing may need external orchestration or future distributed extensions.No runtime conditional branching. Current workflows support static directed acyclic graphs (DAGs) with designtime branching (e.g., parallel branches that merge later). Runtime conditional logic (e.g., "if confidence &gt; 0.8 then branch A else branch B") is not available natively. Users who need conditional behavior can either: (i) create separate workflows for different scenarios, or (ii) implement custom logic within a PGM agent (requiring minimal coding). Builtin branch nodes are planned for a future release.Debugging complexity in nested subgraphs. While recursive subgraph composition reduces implementation effort and eliminates manual postprocessing, deeply nested workflows can introduce debugging challenges. To mitigate this, NeuraGraph persists pernode execution traces and intermediate outputs as structured JSON artifacts (see supplementary material Section 3.1), enabling systematic inspection of failures. However, visualization of nested execution paths remains less intuitive than flat pipeline debugging.Natural language interface is experimental. An experimental natural language interface (similar to Codex/Kimi Code) is under development, allowing users to describe workflows via conversational commands (e.g., "extract chemical-disease relations using Flair NER followed by GPT-4o verification"). This feature is not yet stable or systematically evaluated; therefore it is not included in the current version and will be reported in future work.Limited to supported data formats. Native parsers are provided for CDR, ChemDisGene, and plain text. Adapting NeuraGraph to other biomedical datasets (e.g., i2b2 clinical notes, PICO annotations) requires implementing a custom parser inheriting from the base Parser class, which requires minimal coding (≤50 lines) but may be a barrier for users with no programming experience.Future work will address these limitations by extending support for distributed execution, adding native conditional branching, enhancing debugging visualizations for recursive subgraphs, stabilizing the natural language interface, and expanding the library of prebuilt data parsers.5 ConclusionNeuraGraph establishes a lightweight, minimal-code workflow framework that streamlines the development and evaluation of hybrid LLM-agent pipelines for reproducible biomedical text mining. By integrating real-time workflow validation, recursive subgraph composition, native biomedical benchmark support, and LLM-powered reporting into a pure-Python, zero-infrastructure environment, the framework drastically reduces implementation effort—cutting pipeline setup time from hours to minutes—while maintaining competitive performance on the BioCreative V CDR benchmark. Its enforcement of key research best practices, such as sample-level metric aggregation to avoid pseudoreplication bias and one-command reproducibility via persistent JSON artifacts, ensures scientific rigor. As an open-source tool tailored for standard research lab hardware, NeuraGraph lowers the technical barrier for domain researchers to systematically design, execute, and refine hybrid extraction strategies, facilitating faster empirical comparison and accelerating insights from unstructured biomedical literature.AcknowledgementsThis work was supported by Key Projects of the Fundamental Research Program for Higher Education Institutions in Liaoning Province [LJ232513631003, LJ212513631003].ReferencesAkbik A, Bergmann T, Blythe D et al.
